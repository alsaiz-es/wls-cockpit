# AGENTS.md — WLS Cockpit

Guide for anyone (human or coding agent) changing this repository. Project overview, install and
usage are in [README.md](README.md); contribution rules in [CONTRIBUTING.md](CONTRIBUTING.md).

## What this is

A local operations cockpit for Oracle WebLogic Server, built on the WebLogic REST Management API.
It runs as a small Node HTTP server (`wls-cockpit` CLI) that serves a React app and proxies
same-origin requests to one WebLogic AdminServer. It complements the WebLogic Remote Console with
day-to-day operations on a running domain; it is not a general configuration console.

## Principles

Each principle names the guard that fails when it is broken. Where there is none, it says so.

1. **Passwords never touch disk.** Connection profiles persist without passwords; the password
   lives only in the browser tab's session storage and is never accepted as a CLI option.
   Guard: `app/tests/connection-profiles.test.ts`.
2. **The proxy only talks to a validated WebLogic origin.** Targets with credentials, paths,
   queries or fragments, and non-http(s) schemes are rejected.
   Guard: `app/tests/connection-profiles.test.ts` (proxy target tests).
3. **Mutations sent from Cockpit are recorded in the local action audit**: lifecycle,
   deployment, data source, JMS, JTA and user lockout actions, and every write to the configuration tree
   (`/edit/...`), including ones without a specific rule. Runtime POSTs are matched explicitly
   because WebLogic also uses POST for reads; a new runtime action needs its own rule.
   Guard: `app/tests/action-audit.test.ts`.
4. **Read-only demo mode removes mutation affordances** rather than hiding them with CSS, and
   masks sensitive display values. Guard: `app/tests/demo-readonly-actions.test.ts`.
5. **Both supported WebLogic versions keep working**: 12.2.1.4 and 14.1.2.
   Guard: type checking against both generated clients; behaviour against a real domain is
   checked manually with the visual smoke (`npm run smoke:visual:readonly`).
6. **No real environment data in the repository**: hostnames, IP addresses, usernames,
   passwords, domain paths or captured payloads. Use `wls-admin.example.com`, `127.0.0.1` and
   obvious placeholders. Guard: none automated; review before every commit.
7. **Cockpit does not bundle Oracle jars.** Optional JMS browse/produce over JMX uses jars and a
   JDK supplied by the user. Guard: the `files` list in `app/package.json`.

## Setup and commands

The application lives in `app/`. `npm install` also generates the typed REST client from the
specs in `openapi/` (`postinstall` runs `npm run gen`).

```bash
cd app
npm install
npm run test:unit      # node --test on tests/*.test.ts (Node 22.6+)
npm run lint
npx tsc -b --force
npm run build          # web app + CLI bundle in dist/ and dist-server/
```

All four checks must pass before committing; CI runs them on every push and pull request.

To try a change against a domain: `npm run dev` with `app/.env.local` pointing `VITE_WLS_TARGET`
at an AdminServer (start from `app/.env.example`), or run the built CLI:

```bash
node dist-server/wls-cockpit.mjs --target=http://wls-admin.example.com:7001
```

## Hard constraints

- **Generated REST types** (`app/src/api/generated/`) are gitignored and produced by
  `npm run gen`. Never commit them.
- **`openapi/` holds pinned copies** of the WLS REST specs generated by the sibling project
  [weblogic-rest-openapi](https://github.com/alsaiz-es/weblogic-rest-openapi). Bumping them is a
  `chore(openapi)` commit: copy the new YAMLs, run `npm run gen`, re-run the checks.
- **Mutations against WebLogic only on a disposable or lab domain.** Lifecycle actions,
  deployments, JMS delete/produce and configuration edits change a live domain.
- `app/.env.local` and other local environment files stay gitignored.

## Conventions

- Code, comments, commit messages and public docs in English.
- Small commits with conventional prefixes (`feat`, `fix`, `docs`, `chore`, `test`, `ci`).
  No `Co-Authored-By` or tool attribution trailers.
- UI direction is in [docs/ui/guidelines.md](docs/ui/guidelines.md) and wins over library
  defaults. Reuse the primitives it lists under `app/src/components/`; extend the guidelines in
  the same commit when a new pattern is needed.
- Stack: Vite, React, TypeScript, TanStack Query, React Router, Tailwind CSS with shadcn/ui
  (do not reinvent components), `openapi-typescript` and `openapi-fetch`.
